## 一、主推方向：证据链侦探（横纵调查报告生成器）

**一句话**：输入一个难题，自动拆步骤、多轮元宝搜索、交叉比对，输出一份"横纵分析报告"——正好命中进阶挑战「深度调查」。

为什么是你没注意到的：

1. `Jev_横纵分析报告.md` 证明你已经有一套成熟的调查报告模板：一句话定义 → 纵向（来龙去脉）→ 横向（对比矩阵）→ 交汇判断 → **带访问日期的来源列表**，且坚持"厂商主张 ≠ 已验证事实"分开标注。这就是赛道要的"带证据链的调查报告"，你只是从没把它当成可产品化的流水线。
2. `UserMD/26_10_4.md` 第 5 节的输出规范（已知事实 / 推断部分 / 需验证部分三分，禁止编造，结论→原因→方法→验证）与评审标准"查得准、来源点得开、查不到敢说不知道"逐字对应。**把你的个人协作规范直接写成产品的回答宪法（system prompt）**，反幻觉不是要新学的东西，是你的既有风格。
3. 评审标准"问题越难分越高"——你日常研究的正是难题（例如"决策模型与结构化输出到底差在哪"），演示问题可以直接用你会真问的问题。

最小实现（贴合你的 React/Next.js 技术栈，一晚可完成）：单页 Web 应用，输入问题 → LLM 拆子问题 → 逐个调 SearchPro（Mode=2，自然结果+VR 卡）→ 汇总输出「结论 + 依据（带 date）+ 来源（可点开）+ 分歧标注 + 查不到项」。

## 二、叠加模块 A：持续盯梢（移植你的 Work Review 架构）

**一句话**：你 8 月起自建的 WorkBuddy 自动日报系统（时间戳采集 → AI 分析 → 每日 markdown 报告）与「持续盯梢」挑战（周期性自查 + 有变化就提醒）是同一架构，只差把数据源换成元宝搜索。

- 做法：选 2~3 个不碰时政/个人的盯梢目标（如演唱会/活动余票状态、某开源项目版本动态、赛事报名节点），定时脚本轮询同一 Query → 比对 date 与内容差异 → 按你日报格式写带日期的 markdown + 变化提醒。
- 24 小时内的演示方案：今天跑一次、明天封板前跑一次，两份快照对比即为演示；或诚实标注"历史快照回放"。
- 依据：`04_Self/DayReport/` 每日自动生成、`UserMD` 中"Work Review 项目，基于应用使用时间戳生成每日自动化复盘"（2026-08）。

## 三、叠加模块 B：动画考据题材（用你真正会问的难题演示）

**一句话**：赛道官方示例题材"找一部只记得剧情的剧"，恰好是你的日常——10-21~10-23 连续三天重度观看罗小黑战记 2 万字拉片系列。

- 演示查询用你个人真会问的难题：只记得剧情找作品、台词出处、上映/流媒体档期、作画 staff 考据。"越有人真在用"对你成立：你自己就是用户。
- **红线自查**：近期浏览里含网红个人事件类内容（王扁遇袭、公关漫谈等），这类话题**不得**作为演示查询；考据只限作品与官方公开信息。

## 七、最终决定（2026-10-24 用户锁定）

- **方案：A 证据链侦探（调查报告生成器）**，产品工作名「AI 侦探社」。
- **形态**：Web 应用（Next.js + TypeScript，React 为用户既有栈），双 Tab：
  - **深度调查**（主线）：问题 → LLM 拆题 → 并行元宝搜索（Mode=2）→ 交叉比对 → 三分法报告（结论/依据[事实|推断|待验证]/来源可点/冲突标注/查不到明说）；
  - **持续盯梢**（后置模块，用户指定交互）：调查报告完成后提供「加入盯梢」选项；独立 Tab 管理全部盯梢任务（快照列表 + 变化提醒）。主线完成且有余力才做，卡住即砍。
- **时间预算**：今晚 3-6 小时 MVP（调查链路 + 报告渲染），明早打磨与提交；15:00 封板、16:00 提交。
- **演示**：3 个固定排练的真实查询（含一道动画考据题），录屏/截图；发布帖带四个指定话题。
- **密钥**：腾讯云 SecretId/SecretKey 与 LLM Key 一律环境变量（`.env` 入 `.gitignore`），已在腾讯云完成服务开通与额度领取（用户确认）。
- **UI 设计语言（2026-10-24 晚定稿）**：印刷档案风——暖白纸底 `#fafaf8`、Georgia/宋体衬线标题、四色分区药丸（调查 blue `#536b83` / 事实 teal / 推断 plum / 待验证 ochre）、1px 细线白卡、近黑主按钮、左侧固定窄栏 + 窄阅读栏。此前历经 Vercel Web Interface Guidelines 审计与 quiet-instrument 浅色两轮迭代。
