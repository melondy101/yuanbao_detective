# 检索路径可视化调研（2026-10-25）

> 需求：把深度调查的「问题 → 检索轮 → 来源 → 结论」路径用图谱或其他可视化方式呈现。本文先调研业界实现，给出方案对比与推荐；**尚未实施，等用户拍板**。

## 一、我们的数据形状（决定了图怎么画）

`InvestigationReport` 已持有：question、rounds（3~5 条检索线，各带 resultCount/topTitles）、sources（≤20 条，含 cred 分级、url、date）、evidence.fact[].refs（事实↔来源编号）、conflicts[].refs、selfEval。

天然是**四层有向无环图**：问题 → 检索轮 → 来源 → 事实/冲突。
唯一数据缺口：orchestrator 未记录「每条来源来自哪一轮」（roundsResults→sources 合并时丢了轮次归属），实施时需在来源编号分配处补一个 `roundSources: number[][]` 映射（约 5 行改动）。

## 二、业界实现调研

### 2.1 渲染层：React Flow 是事实标准

- [React Flow (@xyflow/react)](https://reactflow.dev)：MIT 协议，v12 起**支持 React 19**，包名从 `reactflow` 改为 `@xyflow/react`；有官方 [Next.js 示例仓库](https://github.com/xyflow/react-flow-example-apps)和 [AI Workflow Editor 模板](https://reactflow.dev/ui/templates/ai-workflow-editor)。
- 自动布局：官方提供 [dagre 与 elkjs 集成示例](https://reactflow.dev/examples/layout/elkjs)；[Playground](https://xyflow.com/labs/react-flow-playground) 可对比 Dagre/ELK/D3-Hierarchy 三种布局。dagre 简单但已停维护，elkjs 活跃且支持端口/边路由。
- Next.js App Router 两个已知坑：必须 `"use client"` 或 `dynamic import ssr:false`（[SSR 不渲染问题](https://stackoverflow.com/questions/76964275/reactflow-and-next-js-with-app-router-nodes-and-edges-not-rendered)）；CSS 导入顺序与 React Context 会导致[边消失](https://dev.to/nareshipme/why-reactflow-edgedisappear-in-next-js-two-subtle-css-and-context-bugs-jno)。

### 2.2 Agent 轨迹可视化（同类产品怎么画）

- [AgentPrism](https://github.com/evilmartians/agent-prism)（Evil Martians 开源）：OpenTelemetry agent 轨迹 → 可视化图，React 组件库，可直接借鉴其节点/泳道设计。
- [Langfuse](https://langfuse.com/blog/2024-07-ai-agent-observability-with-langfuse)：开源观测平台，带 agent DAG 视图——偏运维，风格与档案风不搭，只借鉴信息架构。
- **Perplexity Deep Research 用的是线性步骤日志，不是图**（[官方博客](https://www.perplexity.ai/hub/blog/introducing-perplexity-deep-research)）——说明"步骤时间线"已是同质化方案，画图才有差异化。

### 2.3 深度研究的"图谱"先例：Co-STORM 思维导图

- 斯坦福 [STORM/Co-STORM](https://github.com/stanford-oval/storm) 维护一棵**动态层级思维导图**（insert / reorganize 两种操作），报告由导图生成（[解读](https://medium.com/@techsachin/creating-dynamic-mindmap-of-information-from-collaborative-discourse-among-llm-agents-with-d2e3f39c4728)）——这是最接近"检索过程即知识图谱"的学术先例，但需要把发现按层级聚类，对我们的 3~5 轮小规模调查是过度设计。
- GraphRAG 系（[Microsoft GraphRAG](https://microsoft.github.io/graphrag)）画的是**知识内容图谱**（实体-关系），不是检索过程；我们展示的是"查了哪里、谁印证了谁"，两者不同物。

## 三、方案对比（按我们场景）

| 方案 | 依赖 | 工作量 | 档案风契合 | 交互 | 风险 |
|---|---|---|---|---|---|
| **A. React Flow + elkjs 画 DAG** | +1 运行时依赖（~50KB gzip） | 1~2 天 | 需大量自定义样式去"去画布感" | 拖拽/缩放/连线全套 | SSR/Context 两坑；封板前引入新依赖风险高 |
| **B. 自绘 SVG 分层路径图（推荐）** | 零依赖 | 半天~1 天 | 完全可控：细线、衬线、分区色直接复用 | 点击节点锚点跳转来源、hover 显标题 | 布局逻辑自己写（4 层固定列布局，复杂度低） |
| **C. Co-STORM 式思维导图** | 图布局库 | 2~3 天+ | 中 | 最炫 | 需要层级聚类，超出当前数据规模；改动大 |
| **D. Perplexity 式线性步骤日志** | 零 | 已有（06 调查过程） | — | — | 无差异化，等于不做 |

## 四、推荐：方案 B「证据链地图」（自绘 SVG 分层图）

- 形态：横向四列——**问题 → 检索线（01~05）→ 来源（带可信徽章色点）→ 结论**；被引用的来源与事实之间连细线，多源交叉的边用分区 teal 色、单一来源用灰，冲突边用赭石——把「反幻觉三件套」的结论直接画进图里。
- 交互：节点点击 = 页面锚点跳转（复用现有 `#src-n` / 编号锚点体系），hover 显示标题/日期；移动端横向滚动。
- 落位：报告 05 自评卡之后（或替代 06 调查过程的纯文字列表，二选一）；历史卷宗重看时同样可用。
- 工程量：`RetrievalGraph.tsx` 一个组件（估 ~250 行）+ orchestrator 补 roundSources 映射；零新依赖、零 SSR 风险、完全贴现有设计语言。
- 营销点：「每份报告自带一张**证据链地图**：查了哪几条线、哪两个独立来源互相印证、哪里冲突，一图看穿。」

## 五、实施清单（拍板后执行）

1. orchestrator：来源分配处记录轮次归属（roundSources）
2. `components/RetrievalGraph.tsx`：SVG 四列布局 + 边渲染 + 锚点跳转
3. ReportView 插入新区块；HistoryTab 自动继承
4. 真实查询验证 + 截图留痕 + 提交
