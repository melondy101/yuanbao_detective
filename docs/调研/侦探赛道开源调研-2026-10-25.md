**赛道评分维度**（每项 0–5 分，满分 30）：

- **查得准**：项目是否含验证、交叉比对、NLI 蕴含、证据检索等"把答案查对"的机制
- **来源点得开**：是否产出可点击的真实来源（引用、溯源、链接透传）
- **敢说不知道**：弃答/不确定性量化/置信校准等机制
- **好用好玩**：有可用 UI/Demo/CLI，能直接上手
- **热度**：GitHub 星数（对数映射）
- **新鲜度**：最近提交时间

## 三、最佳实践（网络检索提炼）

### 3.1 事实核查任务范式（AVeriTeC / FEVER 2025）

- **标准流水线**：声明 → **问题分解** → 子问题证据问答链 → 证据聚合 → 真伪裁定（[AVeriTeC 综述](https://arxiv.org/html/2410.23850v1)、[FEVER 2025 AVeriTeC 2.0](https://fever.ai/2025/task.html)）
- **关键教训**：证据检索质量的自动评估不可靠，2.0 版改用**人工交叉评估**——"来源点得开"必须人能点开验证
- **开放权重系统可打平闭源**（[ACL 2025 FEVER 论文](https://aclanthology.org/2025.fever-1.15.pdf)）

### 3.2 引用与归因的三段验收（业界共识）

[FutureAGI 框架](https://futureagi.com/blog/evaluating-llm-citation-attribution-2026)把引用验收拆成三问，与元宝探长机制可逐条对齐：
1. **是否产出了引用**（emit）——我们的编号锚点 ✓
2. **引用是否可解析**（resolve，指向真实可打开的来源）——URL 原样透传 ✓
3. **来源是否真的支撑该声明**（support）——目前靠 LLM 交叉比对，**可升级为 NLI 蕴含校验**（reverify 的做法）

其他：[ALCE](https://github.com/princeton-nlp/ALCE) 的引用 precision/recall、[RARR](https://arxiv.org/abs/2210.08726) 的事后归因修正、[AttributionBench](https://osu-nlp-group.github.io/AttributionBench)、**弃答率 vs 幻觉率（AR/HR）双指标**（[alphaxiv 2405.02228](https://www.alphaxiv.org/abs/2405.02228)）——三分法报告正是这个 trade-off 的产品化表达。

### 3.3 事实性评测工具箱

[FActScore](https://aclanthology.org/2023.emnlp-main.741)（原子事实分解）→ [FELM](https://arxiv.org/abs/2310.00741)（评测器的评测）→ [SimpleQA Verified](https://arxiv.org/html/2509.07968v2)（短事实性）→ [OpenFactCheck](https://github.com/OpenFactCheck/OpenFactCheck)（组装自己的事实性评测器）。

### 3.4 工程 Pattern（Plan-Execute-Verify-Replan）

- [Anthropic 多 Agent 研究系统](https://www.anthropic.com/engineering/multi-agent-research-system)：主 Agent 拆题 → 并行子 Agent → 综合——与元宝探长编排同构，其"子 Agent 数量按查询复杂度伸缩"值得借鉴
- [VMAO 框架](https://arxiv.org/html/2603.11445v2)：验证驱动的重规划循环（检索失败/验证不过 → 重新拆题）
- [NVIDIA 查询分解](https://docs.nvidia.com/rag/2.4.0/query_decomposition.html)、[RAGFlow 深度研究](https://ragflow.io/blog/ragflow-0.20.0-multi-agent-deep-research)：简单查询不拆、复合查询建 DAG

### 3.5 引用 UX（Perplexity 拆解）

[AI UX Playground 对 Perplexity 引用设计的拆解](https://aiuxplayground.com/teardowns/perplexity/citations)：内联来源 chips、hover 预览、来源面板、[来源可信标签](https://www.perplexity.ai/help-center/en/articles/20260806-understanding-source-labels)（Government / Academic / Trusted）——元宝探长的来源锚点可升级为"hover 预览 + 域名可信标签"两层。

### 3.6 中文生态

[清华 CED 中文谣言数据集](https://github.com/thunlp/Chinese_Rumor_Dataset)、[MCFEND 多源中文假新闻基准](https://hyper.ai/cn/datasets/30429)、[基于事实核查的虚假新闻检测综述](https://arxiv.org/pdf/2401.01717)——做中文题材演示或加"辟谣模式"时的数据底座。

## 四、对元宝探长的可操作借鉴（按性价比排序）

1. **弃答/幻觉双指标自评**（uqlm + AR/HR）：报告里已有"查不到"分区，补一个显式的「本次调查弃答率/幻觉率」自评徽章，直击评审"敢说不知道"维度
2. **NLI 蕴含校验**（reverify 做法）：对"已证实"分区的每条结论跑一次声明-来源蕴含判定，不蕴含的降级为"推断"
3. **来源可信标签**（Perplexity）：给来源域名打 Gov/Academic/Trusted 标签（政府/学术/百科/媒体），与现有"权威信源优先"策略配套可视化
4. **SearXNG 式多源交叉**：同一条结论至少两个独立域名的来源才进"已证实"
5. **引用三段验收自检**（emit/resolve/support）：上线前用 ALCE 思路对 20 个真实查询做引用 precision 抽检
